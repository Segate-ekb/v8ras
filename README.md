# v8ras

Клиент сервера администрирования кластера **1С:Предприятие** (RAS) на чистом
**OneScript**. Разговаривает с `ras` напрямую по его протоколу: не нужны ни `rac`,
ни установленная платформа, работает на любой ОС, где есть OneScript. Версия
протокола согласуется с сервером автоматически.

Что умеет: читать кластеры, сеансы, соединения, рабочие процессы и серверы,
лицензии, блокировки и информационные базы; завершать сеансы и рвать соединения;
создавать, настраивать и блокировать базы; управлять администраторами кластера и
агента; регистрировать кластеры и рабочие серверы. Полный список методов, структур
и прав — в [описании API](docs/api.md).

## Установка

```
opm install v8ras
```

Требуется OneScript 2.2.1 или новее. Других зависимостей нет.

## Быстрый старт

```bsl
#Использовать v8ras

Клиент = Новый КлиентКластераRAS("app-srv", 1545);
Клиент.Подключить();

Для Каждого Кластер Из Клиент.Кластеры() Цикл
	Клиент.АутентифицироватьКластер(Кластер.Ид, "ClusterAdmin", "секрет");
	Сеансы = Клиент.Сеансы(Кластер.Ид);
	Сообщить(Кластер.Имя + ": сеансов " + Сеансы.Количество());
КонецЦикла;

Клиент.Отключить();
```

`"app-srv", 1545` — адрес и порт `ras`. Если у кластера нет администраторов,
имя и пароль можно передать пустыми.

## Доступ

У кластера 1С три круга прав, и каждый открывается своим методом:

| Кому | Метод | Что открывает |
| --- | --- | --- |
| администратор кластера | `АутентифицироватьКластер` | сеансы, процессы, серверы, базы, блокировки, список администраторов — всё для мониторинга |
| администратор агента | `АутентифицироватьАгент` | администраторы агента и регистрация кластеров |
| пользователь базы | `АутентифицироватьБазу` | настройки, удаление и блокировка конкретной базы |

Пока администраторов нет, кластер открыт любому, кто дотянулся до порта `ras`.
Как посмотреть администраторов, завести первого и работать с закрытым кластером —
в разделе [«Доступ»](docs/api.md#доступ-кто-и-что-может) описания API.

## Платформы

Работает с любой платформой 8.3, где запущен `ras`. Чем новее платформа, тем
больше полей приходит в структурах; на старой платформе недостающие поля
заполняются значениями по умолчанию. Метод, которого на платформе сервера ещё
нет, не вызывается молча: ошибка называет, с какой версии платформы он доступен.
Сквозные тесты идут на четырёх платформах — 8.3.20, 8.3.24, 8.3.27 и 8.5.1.
Таблица полей по платформам — в [описании API](docs/api.md#платформы).

## Ошибки

Все ошибки — исключения с текстом, начинающимся на `SWP:`. Сервер недоступен, не
принял версию протокола, отказал в операции («administrator is not
authenticated») — текст говорит, что случилось. Расшифровка — в
[описании API](docs/api.md#ошибки).
