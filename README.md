# v8ras

Нативный клиент сервера администрирования кластера **1С:Предприятие** (RAS) на
чистом **OneScript**. Говорит с RAS напрямую по бинарному протоколу поверх TCP:
без вызова `rac`, без установленной платформы, кроссплатформенно. Версия
протокола определяется автоматически при подключении.

Библиотека задумана как сателлит сбора метрик кластера: сеансы, соединения,
рабочие процессы, память, вызовы, лицензии — для последующего экспорта
(например, в OpenTelemetry).

```bsl
Клиент = Новый КлиентКластераRAS("app-srv", 1545);
Клиент.Подключить();

Для Каждого Кластер Из Клиент.Кластеры() Цикл
	Клиент.АутентифицироватьКластер(Кластер.Ид, "Админ", "");
	Сеансы = Клиент.Сеансы(Кластер.Ид);
	Сообщить(Кластер.Имя + ": сеансов " + Сеансы.Количество());
КонецЦикла;

Клиент.Отключить();
```

## Почему нативно, а не через rac

`rac` — бинарь платформы: его версия жёстко связана с версией сервера, он есть
не везде, а на подвисшем `ras` зависает без таймаута. Прямой разговор по
протоколу RAS убирает зависимость от платформы на машине сателлита и даёт
управляемый сетевой ввод-вывод.

## Автоопределение версии

При открытии административной конечной точки клиент запрашивает последнюю
известную библиотеке версию сервиса. Сервер поддерживает диапазон версий вниз
от своей, поэтому запрос работает и против более нового сервера. Если сервер
версию не принял, он присылает список поддерживаемых — клиент берёт высшую
общую. Если общих версий нет (сервер новее всего, что знает библиотека), клиент
падает с понятной ошибкой: какую версию просили, что поддерживает сервер, что
знает библиотека. Это сигнал обновить `v8ras` под новую версию платформы.

## Состав

| Что | Где | Назначение |
| --- | --- | --- |
| `КлиентКластераRAS` | `src/Классы` | публичный API: подключение, аутентификация, чтение сущностей |
| кодек (`БуферЗаписи`, `БуферЧтения`) | `src/internal/Классы` | примитивы бинарного протокола: целые от старшего байта, две схемы varint, строки, UUID, время |
| транспорт (`СоединениеRAS`, `РукопожатиеRAS`, `КонечнаяТочка`) | `src/internal/Классы` | кадрирование пакетов, рукопожатие, обмен сообщениями конечной точки |
| `ПротоколRAS`, `СущностиRAS` | `src/internal/Модули` | константы протокола и разбор сущностей |

Низкоуровневые классы `src/internal` — внутренние и меняются без оглядки на
обратную совместимость.

## Возможности

Реализовано: подключение и рукопожатие с автоопределением версии,
аутентификация агента и кластера, чтение списка кластеров, сеансов (с метриками
памяти, вызовов, длительностей, процессорного времени и числом лицензий) и
соединений.

В планах: рабочие процессы и рабочие серверы (поля с плавающей точкой),
блокировки, информационные базы, менеджеры.

## Требования

OneScript 2.2.1+. Внешних зависимостей времени выполнения нет — только
стандартная библиотека (TCP и работа с двоичными данными).

## Тесты

```
oneunit execute
```

Кодек проверяется по эталонным байтам протокола, кадрирование — по петле на
реальном TCP-сокете, рукопожатие и разбор сущностей — на сокете-сценарии с
заготовленными ответами сервера. Проверка против живого RAS с сервером 1С
выполняется в CI (workflow e2e, при наличии секретов стенда).
