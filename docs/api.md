# API клиента RAS

Вся работа идёт через один объект — `КлиентКластераRAS`. Он подключается к серверу
администрирования (`ras`), а дальше читает и меняет кластер методами, перечисленными
ниже. Идентификаторы кластеров, баз, сеансов и прочего — строки UUID в том виде, в
каком их отдаёт сервер (как в `rac` и консоли администрирования). Списки — массивы
структур с русскоязычными полями; состав полей каждой структуры — в разделе
[Структуры](#структуры).

## Подключение

```bsl
Клиент = Новый КлиентКластераRAS("app-srv", 1545);
Клиент.Подключить();

Сообщить(Клиент.ВерсияСервиса()); // например "22.0"
// ... работа с кластером ...

Клиент.Отключить();
```

Конструктор: `Новый КлиентКластераRAS(Хост, Порт, Версия, ТаймаутСекунд)`.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `Хост` | `"localhost"` | адрес машины, где запущен `ras` |
| `Порт` | `1545` | порт `ras` |
| `Версия` | `Неопределено` | версия сервиса администрирования; `Неопределено` — согласовать с сервером автоматически |
| `ТаймаутСекунд` | `30` | предел ожидания ответа сервера |

| Метод | Что делает |
| --- | --- |
| `Подключить()` | открывает TCP-соединение и согласует версию сервиса; возвращает сам клиент, можно писать `Новый КлиентКластераRAS(...).Подключить()` |
| `ВерсияСервиса()` | согласованная версия сервиса, строка вида `"16.0"` |
| `ВерсияАгента()` | версия платформы на сервере, строка вида `"8.3.27.1859"`; доступно с платформы 8.3.16 |
| `Отключить()` | закрывает соединение; повторный вызов безопасен |

Версия сервиса согласуется сама: клиент просит самую новую известную ему, сервер
либо принимает её, либо присылает свой список, и клиент берёт высшую общую. Задавать
`Версия` вручную нужно только для отладки. Одно соединение — одна аутентификация:
права, полученные вызовами из следующего раздела, живут до `Отключить()`.

## Доступ: кто и что может

В кластере 1С три независимых круга прав. Клиент получает их тремя методами, и
каждый нужен только для своей части операций.

| Круг | Метод | Для чего нужен |
| --- | --- | --- |
| Администраторы агента (центрального сервера, `ragent`) | `АутентифицироватьАгент(Пользователь, Пароль)` | список администраторов агента и управление им, регистрация кластера на агенте |
| Администраторы кластера | `АутентифицироватьКластер(ИдКластера, Пользователь, Пароль)` | всё остальное внутри кластера: сеансы, соединения, процессы, серверы, базы, блокировки, администраторы кластера |
| Пользователи информационной базы | `АутентифицироватьБазу(ИдКластера, Пользователь, Пароль)` | операции с конкретной базой: полное описание, изменение, удаление, блокировка сеансов, блокировки базы и сеанса |

Главное правило: **пока список администраторов пуст, доступ открыт всем.** На свежем
кластере администраторов нет, и любой, кто дотянулся до порта `ras`, может читать
сеансы и завершать их. Первый зарегистрированный администратор закрывает кластер:
с этого момента каждое соединение обязано представиться. То же для агента. Для
информационной базы роль «администраторов» играют её пользователи: пока в базе нет
ни одного пользователя, `АутентифицироватьБазу` не нужна.

Аутентификация в библиотеке — по имени и паролю. Администратора, у которого
разрешена только аутентификация операционной системой, библиотека использовать не
сможет. Список кластеров (`Кластеры()`) доступен без аутентификации всегда.

### Посмотреть, кто администрирует кластер

```bsl
Клиент = Новый КлиентКластераRAS("app-srv", 1545).Подключить();
ИдКластера = Клиент.Кластеры()[0].Ид;

// на закрытом кластере сперва представляемся, иначе будет исключение «not authenticated»
Клиент.АутентифицироватьКластер(ИдКластера, "ClusterAdmin", "секрет");

Для Каждого Админ Из Клиент.АдминистраторыКластера(ИдКластера) Цикл
	Способ = "";
	Если Админ.АутентификацияПаролем Тогда
		Способ = "пароль";
	КонецЕсли;
	Если Админ.АутентификацияОС Тогда
		Способ = Способ + " ОС: " + Админ.ПользовательОС;
	КонецЕсли;
	Сообщить(Админ.Имя + " (" + Админ.Описание + "): " + СокрЛП(Способ));
КонецЦикла;
```

Пустой список означает открытый кластер.

### Закрыть кластер: завести первого администратора

```bsl
Клиент = Новый КлиентКластераRAS("app-srv", 1545).Подключить();
ИдКластера = Клиент.Кластеры()[0].Ид;

Админ = Новый Структура;
Админ.Вставить("Имя", "ClusterAdmin");
Админ.Вставить("Пароль", "секрет");
Админ.Вставить("Описание", "Администратор кластера");
// АутентификацияПаролем = Истина уже по умолчанию

Клиент.ЗарегистрироватьАдминаКластера(ИдКластера, Админ);
```

Пока администраторов не было, аутентификация для этого вызова не требовалась. Сразу
после него кластер закрыт: даже это же соединение для следующих операций должно
представиться, а новое соединение — обязательно:

```bsl
Клиент = Новый КлиентКластераRAS("app-srv", 1545).Подключить();
ИдКластера = Клиент.Кластеры()[0].Ид;
Клиент.АутентифицироватьКластер(ИдКластера, "ClusterAdmin", "секрет");

Сеансы = Клиент.Сеансы(ИдКластера); // теперь можно
```

Добавить второго администратора может только уже аутентифицированный администратор.
Структура администратора:

| Поле | Назначение | С платформы |
| --- | --- | --- |
| `Имя` | имя для входа, обязательно | |
| `Описание` | произвольный комментарий | |
| `Пароль` | пароль; хранится сервером, обратно не читается (в списке приходит пустым) | |
| `АутентификацияПаролем` | разрешён вход по паролю; по умолчанию `Истина` | |
| `АутентификацияОС` | разрешён вход пользователем ОС; по умолчанию `Ложь` | |
| `ПользовательОС` | пользователь ОС вида `\\DOMAIN\user` или `user@domain`, если включена `АутентификацияОС` | |
| `ПарольТолькоСЛокальногоХоста` | вход по паролю разрешён только с машины сервера; по умолчанию `Ложь` (`rac` по умолчанию ставит `Истина`) | 8.3.27 со сборки 2342 |
| `АутентификацияКлючом` | разрешён вход по открытому ключу; по умолчанию `Ложь` | 8.3.27 со сборки 2342 |
| `ОткрытыйКлюч` | открытый ключ администратора, если включена `АутентификацияКлючом` | 8.3.27 со сборки 2342 |

Удаление — по имени: `Клиент.УдалитьАдминаКластера(ИдКластера, "ClusterAdmin")`.
Удалив последнего администратора, вы снова открываете кластер всем.

### Администраторы агента

Это отдельный список, он хранится центральным сервером и не пересекается с
администраторами кластера. Нужен редко: только чтобы управлять самим списком и
регистрировать на агенте новые кластеры.

```bsl
Клиент = Новый КлиентКластераRAS("app-srv", 1545).Подключить();
Клиент.АутентифицироватьАгент("AgentAdmin", "секрет"); // на открытом агенте — не нужно

Для Каждого Админ Из Клиент.АдминистраторыАгента() Цикл
	Сообщить(Админ.Имя);
КонецЦикла;

Админ = Новый Структура("Имя,Пароль,Описание", "AgentAdmin2", "секрет2", "Запасной");
Клиент.ЗарегистрироватьАдминаАгента(Админ);
Клиент.УдалитьАдминаАгента("AgentAdmin2");
```

### Доступ к информационной базе

Операции над конкретной базой сервер пропускает только от имени пользователя этой
базы с административными правами. Клиент добавляет учётные данные вызовом
`АутентифицироватьБазу`; сервер подбирает подходящие к каждой базе сам, поэтому для
нескольких баз вызов делают несколько раз.

```bsl
Клиент.АутентифицироватьКластер(ИдКластера, "ClusterAdmin", "секрет");
Клиент.АутентифицироватьБазу(ИдКластера, "Администратор", "пароль-в-базе");

База = Клиент.ИнформацияОБазе(ИдКластера, ИдБазы);
Клиент.ЗаблокироватьСеансы(ИдКластера, ИдБазы, "Регламентные работы до 23:00", "allow");
```

### Минимальные права для мониторинга

Для сбора метрик (сеансы, соединения, процессы, лицензии, блокировки кластера)
достаточно одного администратора кластера с паролем. Администратор агента и
пользователи баз не нужны.

## Методы

Колонка «Доступ» — какой из трёх кругов прав должен быть получен на этом соединении,
если кластер или база закрыты. Методы работают на любой платформе 8.3 с запущенным
`ras`, кроме отмеченных «с 8.3.11» (потребление ресурсов), `ВерсияАгента()` (с 8.3.16)
и `ВыключитьРабочийПроцесс()` (с 8.3.27);
состав полей в ответах растёт с версией платформы — см. [Платформы](#платформы).

### Чтение

| Метод | Возвращает | Доступ |
| --- | --- | --- |
| `Кластеры()` | массив [Кластер](#кластер) — кластеры, зарегистрированные на агенте | не нужен |
| `Менеджеры(ИдКластера)` | массив [Менеджер](#менеджер) — менеджеры кластера (`rmngr`) | администратор кластера |
| `РабочиеСерверы(ИдКластера)` | массив [Сервер](#сервер) | администратор кластера |
| `РабочиеПроцессы(ИдКластера)` | массив [Процесс](#процесс) — с лицензиями, памятью и производительностью | администратор кластера |
| `Инфобазы(ИдКластера)` | массив [БазаКратко](#базакратко) — список баз без настроек | администратор кластера |
| `ИнформацияОБазе(ИдКластера, ИдБазы)` | [База](#база) — полное описание с настройками | администратор кластера и пользователь базы |
| `Сеансы(ИдКластера)` | массив [Сеанс](#сеанс) — все сеансы кластера | администратор кластера |
| `Соединения(ИдКластера)` | массив [Соединение](#соединение) | администратор кластера |
| `Блокировки(ИдКластера)` | массив [Блокировка](#блокировка) — управляемые блокировки кластера | администратор кластера |
| `БлокировкиБазы(ИдКластера, ИдБазы)` | массив [Блокировка](#блокировка) | администратор кластера и пользователь базы |
| `БлокировкиСоединения(ИдКластера, ИдСоединения)` | массив [Блокировка](#блокировка) | администратор кластера |
| `БлокировкиСеанса(ИдКластера, ИдБазы, ИдСеанса)` | массив [Блокировка](#блокировка) | администратор кластера и пользователь базы |
| `Сервисы(ИдКластера)` | массив [Сервис](#сервис) — сервисы кластера и менеджеры, на которых они работают | администратор кластера |
| `АдминистраторыКластера(ИдКластера)` | массив [Администратор](#администратор) | администратор кластера |
| `АдминистраторыАгента()` | массив [Администратор](#администратор) | администратор агента |

### Сеансы и соединения

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `ЗавершитьСеанс(ИдКластера, ИдСеанса, Сообщение = "")` | принудительно завершает сеанс; `Сообщение` увидит пользователь | администратор кластера |
| `ПрерватьСерверныйВызов(ИдКластера, ИдСеанса, Сообщение = "")` | прерывает текущий серверный вызов сеанса, сеанс остаётся; `Сообщение` — текст ошибки в прерванном вызове | администратор кластера |
| `РазорватьСоединение(ИдКластера, ИдПроцесса, ИдСоединения)` | разрывает соединение с рабочим процессом; `ИдПроцесса` — поле `ИдПроцесса` структуры [Соединение](#соединение) | администратор кластера |

Завершить все сеансы одной базы:

```bsl
Для Каждого Сеанс Из Клиент.Сеансы(ИдКластера) Цикл
	Если Сеанс.ИдБазы = ИдБазы Тогда
		Клиент.ЗавершитьСеанс(ИдКластера, Сеанс.Ид, "Сервер уходит на обслуживание");
	КонецЕсли;
КонецЦикла;
```

### Рабочие процессы

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `ВыключитьРабочийПроцесс(ИдКластера, ИдПроцесса)` | выключает рабочий процесс (`rphost`): кластер сразу запускает замену, а выключенный процесс останавливает по истечении `ПериодПринудительногоЗавершения` кластера; при 0 — только когда вернутся все его вызовы. Затрагивает все базы процесса; с 8.3.27 | администратор кластера |

Выключение асинхронное: сразу после вызова процесс ещё числится включённым, через доли секунды
у него `Включен = Ложь`, после остановки — `Запущен = Ложь`. Сервер не проверяет `ИдПроцесса`:
на несуществующий процесс ошибки нет.

### Информационные базы

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `СоздатьБазу(ИдКластера, Инфо, Режим = 1)` | регистрирует базу в кластере и возвращает её UUID. `Инфо` — структура с полями [База](#база): обязательны `Имя`, `СУБД`, `СерверБД`, `ИмяБД`, `ПользовательБД`, `ПарольБД`, `Локаль`; остальные — по умолчанию. `Режим` `1` — создать базу данных на сервере СУБД, `0` — только зарегистрировать существующую | администратор кластера |
| `ОбновитьБазу(ИдКластера, Инфо)` | записывает настройки базы целиком. Берите структуру из `ИнформацияОБазе`, меняйте нужные поля и передавайте обратно | администратор кластера и пользователь базы |
| `УдалитьБазу(ИдКластера, ИдБазы, Режим = 0)` | `0` — снять с регистрации, оставив базу данных; `1` — удалить базу данных; `2` — очистить базу данных | администратор кластера и пользователь базы |
| `ЗаблокироватьСеансы(ИдКластера, ИдБазы, Сообщение = "", КодРазрешения = "")` | включает блокировку начала сеансов; `КодРазрешения` пропускает тех, кто укажет его в параметрах запуска (`/UC`) | администратор кластера и пользователь базы |
| `РазблокироватьСеансы(ИдКластера, ИдБазы)` | снимает блокировку начала сеансов | администратор кластера и пользователь базы |

Зарегистрировать существующую базу PostgreSQL:

```bsl
Инфо = Новый Структура;
Инфо.Вставить("Имя", "trade");
Инфо.Вставить("Описание", "Торговля");
Инфо.Вставить("СУБД", "PostgreSQL");           // MSSQLServer, PostgreSQL, IBMDB2, OracleDatabase
Инфо.Вставить("СерверБД", "pg.lan");
Инфо.Вставить("ИмяБД", "trade");
Инфо.Вставить("ПользовательБД", "postgres");
Инфо.Вставить("ПарольБД", "секрет");
Инфо.Вставить("Локаль", "ru_RU");
ИдБазы = Клиент.СоздатьБазу(ИдКластера, Инфо, 0);
```

### Администраторы

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `ЗарегистрироватьАдминаКластера(ИдКластера, Админ)` | добавляет администратора кластера; `Админ` — структура [Администратор](#администратор) | администратор кластера (на открытом кластере — не нужен) |
| `УдалитьАдминаКластера(ИдКластера, Имя)` | удаляет администратора по имени | администратор кластера |
| `ЗарегистрироватьАдминаАгента(Админ)` | добавляет администратора агента | администратор агента (на открытом агенте — не нужен) |
| `УдалитьАдминаАгента(Имя)` | удаляет администратора агента | администратор агента |

### Топология кластера

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `ЗарегистрироватьКластер(Инфо)` | создаёт кластер на агенте, возвращает UUID. `Инфо` — структура [Кластер](#кластер); достаточно `Хост`, `Порт`, `Имя`, остальное — умолчания сервера | администратор агента |
| `УдалитьКластер(ИдКластера)` | снимает кластер с агента | администратор кластера |
| `ЗарегистрироватьСервер(ИдКластера, Инфо)` | добавляет рабочий сервер, возвращает UUID. `Инфо` — структура [Сервер](#сервер); достаточно `ХостАгента`, `ПортАгента`, `Имя` | администратор кластера |
| `УдалитьСервер(ИдКластера, ИдСервера)` | убирает рабочий сервер из кластера | администратор кластера |

### Требования назначения

Требования назначения функциональности задаются для рабочего сервера и говорят
кластеру, какие базы и приложения на нём размещать. Изменения вступают в силу после
`ПрименитьТребованияНазначения`.

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `ТребованияНазначения(ИдКластера, ИдСервера)` | массив [ТребованиеНазначения](#требованиеназначения) сервера по порядку | администратор кластера |
| `ТребованиеНазначения(ИдКластера, ИдСервера, ИдТребования)` | одно требование | администратор кластера |
| `ДобавитьТребованиеНазначения(ИдКластера, ИдСервера, Инфо, Позиция = 0)` | добавляет требование на место `Позиция` (с нуля), возвращает UUID. `Инфо` — структура [ТребованиеНазначения](#требованиеназначения) без `Ид` | администратор кластера |
| `УдалитьТребованиеНазначения(ИдКластера, ИдСервера, ИдТребования)` | удаляет требование | администратор кластера |
| `ПрименитьТребованияНазначения(ИдКластера, Полностью = Истина)` | применяет требования: `Истина` — перераспределить всё, `Ложь` — только то, что им противоречит | администратор кластера |

```bsl
Клиент.ПрименитьТребованияНазначения(ИдКластера);
```

### Потребление ресурсов

Счётчики накапливают потребление ресурсов по пользователям или разделителям, ограничения
реагируют на превышение. Доступно с платформы 8.3.11; на более старом сервере эти методы
падают с ошибкой о версии (см. [Платформы](#платформы)).

| Метод | Что делает | Доступ |
| --- | --- | --- |
| `Счётчики(ИдКластера)` | массив [Счётчик](#счётчик) | администратор кластера |
| `Счётчик(ИдКластера, Имя)` | счётчик по имени | администратор кластера |
| `ЗаписатьСчётчик(ИдКластера, Инфо)` | создаёт или обновляет счётчик. `Инфо` — структура [Счётчик](#счётчик), ключ — `Имя` | администратор кластера |
| `УдалитьСчётчик(ИдКластера, Имя)` | удаляет счётчик | администратор кластера |
| `ЗначенияСчётчика(ИдКластера, Имя, Объект = "")` | массив [ЗначениеСчётчика](#значениесчётчика) — текущие значения по объектам учёта; `Объект` вида `"infobase=trade;user=Иванов"`, пусто — все | администратор кластера |
| `НакопленныеЗначенияСчётчика(ИдКластера, Имя, Объект = "")` | то же для накопленных значений | администратор кластера |
| `ОчиститьЗначенияСчётчика(ИдКластера, Имя, Объект = "")` | сбрасывает накопленные значения | администратор кластера |
| `Ограничения(ИдКластера)` | массив [Ограничение](#ограничение) | администратор кластера |
| `Ограничение(ИдКластера, Имя)` | ограничение по имени | администратор кластера |
| `ЗаписатьОграничение(ИдКластера, Инфо)` | создаёт или обновляет ограничение. `Инфо` — структура [Ограничение](#ограничение), ключ — `Имя` | администратор кластера |
| `УдалитьОграничение(ИдКластера, Имя)` | удаляет ограничение | администратор кластера |

```bsl
// Память и вызовы по пользователям за 10 минут
Счётчик = Новый Структура("Имя,ПериодСбора,АнализироватьПамять,АнализироватьВызовы", "users-10min", 600, Истина, Истина);
Клиент.ЗаписатьСчётчик(ИдКластера, Счётчик);

// Прерывать вызов, если пользователь набрал больше 4 ГБ за период
Ограничение = Новый Структура("Имя,Счётчик,Действие,Память,Сообщение",
	"mem-4g", "users-10min", 2, 4 * 1024 * 1024 * 1024, "Слишком много памяти");
Клиент.ЗаписатьОграничение(ИдКластера, Ограничение);

Для Каждого Значение Из Клиент.ЗначенияСчётчика(ИдКластера, "users-10min") Цикл
	Сообщить(Значение.Объект + ": " + Значение.Память + " байт, " + Значение.Вызовы + " вызовов");
КонецЦикла;
```

## Структуры

Поля перечислены так, как они называются в возвращаемых структурах. Поля,
появившиеся в поздних версиях платформы, отмечены в колонке «С платформы»; пустая

## Платформы

Версия платформы определяет, какую версию сервиса администрирования согласует
клиент, а она — состав полей в структурах (колонки «С платформы» выше):

| Платформа | Версия сервиса |
| --- | --- |
| 8.3.11 | 4.0 |
| 8.3.12 | 5.0 |
| 8.3.13 | 6.0 |
| 8.3.14 | 7.0 |
| 8.3.15 | 8.0 |
| 8.3.16 | 9.0 |
| 8.3.17 | 10.0 |
| 8.3.20 — 8.3.22 | 11.0 |
| 8.3.23 | 12.0 |
| 8.3.24 | 13.0 |
| 8.3.25 | 14.0 |
| 8.3.26 | 15.0 |
| 8.3.27 до сборки 2342 | 16.0 |
| 8.3.27 со сборки 2342, 8.5.1 | 22.0 |

Строки с 8.3.20 сняты с живых серверов, более ранние — по Java API администрирования
1С. Платформа старше 8.3.11 согласует версию 3.0: подключение и остальные методы работают,
поля поздних версий приходят со значениями по умолчанию.

Если метод появился позже, чем платформа сервера, запрос на сервер не уходит —
клиент сразу падает с понятной ошибкой:

```
RAS: ВерсияАгента() доступен на сервере 1С не ниже 8.3.16 (версия сервиса администрирования 9.0); подключён сервер с версией сервиса 8.0 (8.3.15)
```

Так ведут себя `ВерсияАгента()` (с 8.3.16), `ВыключитьРабочийПроцесс()` (с 8.3.27) и методы раздела
[Потребление ресурсов](#потребление-ресурсов) (с 8.3.11). Сквозные тесты в CI идут на четырёх
платформах с разными версиями сервиса: 8.3.20, 8.3.24, 8.3.27 и 8.5.1; каждый набор помечен
минимальной платформой и запускается только там, где его возможность доступна.

## Ошибки

Любая проблема — исключение с текстом, начинающимся на `SWP:`.

| Текст | Что значит и что делать |
| --- | --- |
| `SWP: нет ответа от сервера …` | `ras` недоступен или не ответил за `ТаймаутСекунд`: проверьте адрес, порт и что `ras` запущен |
| `SWP: сервер не принял версию … поддерживает …` | сервер новее библиотеки, общих версий сервиса нет: обновите `v8ras` |
| `SWP: исключение сервиса на запрос N: <класс>: <сообщение сервера>` | сервер отказал в операции; сообщение — его собственное. Чаще всего `… administrator is not authenticated` — не вызвана или не прошла аутентификация нужного круга; `Infobase not found`, `Session not found` — объект уже исчез |
| `SWP: ответ обрывается …` | сервер прислал поля, которых библиотека не знает: сообщите версию платформы в issue |
| `RAS: <метод>() доступен на сервере 1С не ниже …` | метод появился позже, чем платформа сервера; запрос на сервер не отправлялся. Нужна платформа не ниже названной |
